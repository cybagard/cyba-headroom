Why headroom

Three agents build at once, and the Mac swaps.

Orca runs several coding agents in parallel, each in its own worktree. Each agent starts containers and VMs that share one pool of unified memory. No layer sees the others, so the fleet fills the host, every agent slows down, and nothing reports why.

STEP 1

An agent calls docker, podman or tart

The call goes through a shim first on the agent's PATH. The shim asks the daemon whether the call fits in the budget.

→
STEP 2

The daemon checks the budget

It subtracts the reserved memory of every container, VM and loaded model from the host total. It then applies the policy.

→
allowedThe call runs as usual.

The container or VM starts, and the daemon attributes it to the agent's worktree.

deniedThe call does not run.

The agent reads what it can reuse or stop. With BUDGET_WAIT=1 the call waits for room instead.

NOTEThe gate is cooperative, not a security boundary. An agent can call the real binary or the Docker socket directly. headroom detects such a start and marks it, but it does not prevent it.

Features

One glance answers who costs what.

01

One row for each worktree

The view shows each Orca worktree with its agents, containers, Tart VMs, CPU and agent memory. The headroom figure and the memory pressure lead the top line.

02

Every resource has an owner

Each container, VM and loaded model belongs to a worktree, or the view lists it as unattributed. Orphans from finished worktrees show up in minutes.

03

Agents negotiate, they do not crash

A denied call tells the agent what to reuse, what to stop, or how to wait. It does not receive an out-of-memory kill or an unclear Tart error.

04

Fails open

When the daemon is down, each call runs and shows a warning. A crashed monitor does not block your build.

The pressure word

  • ✓
    normal is green. The host has room. Start the next agent.
  • ✓
    warn is yellow. The host is close to its limit. The trend in brackets tells how long it was at that level in the last five minutes.
  • ✓
    critical is red. The host swaps. Look for the row with the most agent memory, and stop or reuse what it holds.

The rows

  • ✓
    One row for each worktree. Agents, containers, Tart VMs, CPU and agent memory. The last row lists what belongs to no worktree.
  • ✓
    The flag ⚑ marks a hold while idle. A worktree keeps containers or VMs while none of its agents works. You can release that memory.
  • ✓
    The sign ⚠ marks a start without a check. A container or VM did not go through the gate. A ? means unknown, and unknown is not 0.
Layers

Three layers, from the host to one call.

The daemon samples the host. The lease book attributes each reservation to a worktree. The shim gates one call at a time.

1

Host budget

The daemon reads the host total, the memory pressure and the swap. It subtracts a baseline for the host itself and what LM Studio and Ollama reserve.

2

Worktree leases

Each container, VM and model has a lease that names its Orca worktree. The policy caps one worktree and keeps a minimum headroom for all of them.

3

The gated call

A shim parses one docker, podman or tart call, asks for the memory it will reserve, and receives one verdict.

  • ALLOWEDThe call runs. Exit code of the tool.
  • DENIEDThe container or VM does not start. Exit code 75 and a reason on stderr.
  • WAITINGWith BUDGET_WAIT=1, the call waits for room or for a macOS VM slot, up to 10 minutes.
Coverage

What headroom sees, and what it gates.

headroom runs on macOS on Apple silicon. It finds each worktree through Orca. A call from outside an Orca worktree is not gated.

Pressure levels

WordColourWhat you do
normalgreenStart the next agent.
warnyellowDo not start more. Watch the trend.
criticalredStop or reuse what the top row holds.
?noneUnknown. Run headroom doctor.

Note: Apple's licence permits two macOS VMs on one Apple silicon Mac, and the Virtualization framework enforces it. headroom counts the slots (budget.max_macos_vms, default 2) and denies the third macOS tart run before Tart fails. Linux guests do not count.

Quickstart

Install headroom.

You must have Homebrew and Orca. The service starts the daemon now and at login, and it puts the shims in ~/.config/headroom/shims.

Install and start the service

Homebrew installs the binary and the LaunchAgent. Do not also run headroom install.

brew install cybagard/tap/headroom
brew services start headroom

Launch each agent through the gate

In Orca, open Settings → Agents and set the command of each agent. An agent that already runs keeps its old PATH until you restart it.

headroom run -- claude

Check a shell

Each line tells you what to fix. A login shell puts the real docker first on PATH, so its calls are not gated.

$ headroom doctor
headroom doctor
  ✓ config      ~/.config/headroom/config.toml (no file: defaults in effect)
  ✓ shims       docker, podman, tart in ~/.config/headroom/shims → /opt/homebrew/bin/headroom
  ✓ daemon      running at ~/.config/headroom/d.sock, under Homebrew's LaunchAgent (brew services)

Read a denial

A denied call exits 75. The first line gives the reason and what the worktree holds. The last line tells the agent what helps.

$ docker run -m 12g build-ci
headroom: not starting `docker run` (≈ 13.6 GB) for worktree "fix-login": only 9.2 GB headroom, and 6.0 GB must stay free. Your worktree holds: db (2.0 GB), web (1.0 GB)
headroom: retry later, or run it with BUDGET_WAIT=1 to wait for room

Set the policy

Record some samples, then let headroom suggest propose values. Write them to ~/.config/headroom/config.toml.

# example values, not defaults
[policy]
min_headroom_gb = 6
per_worktree_cap_gb = 12

[budget]
host_baseline_gb = 10

Run the fleet without the swap.

Install headroom, launch your agents through the gate, and let the top line tell you when to stop.
